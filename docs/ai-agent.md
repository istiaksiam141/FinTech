# Assistant behavior

The assistant has two paths. Tuition calculations, savings targets and projections, budget summaries, exchange-rate explanations, and provider quote comparisons remain deterministic browser-side behavior using `lib/finance.js`. These results do not come from a language model. The zero-gap wording continues to say that no additional monthly savings are needed. Quote validation checks fields, currency, and the documented 24-hour freshness window; it does not authenticate a provider quote.

General questions can use Groq's OpenAI-compatible Chat Completions API through `api/assistant.js`, hosted as a Vercel function. The browser sends only the question. The UI warns students not to include names, student IDs, account details, or other sensitive information. The backend rejects extra fields, including financial context and quote details, and returns only a bounded answer. Its system instructions request a direct, friendly answer in simple English, concise paragraphs, and headings, bullets, or numbered steps when useful. They prohibit financial calculations, invented rates/offers, verification claims, account access, and payment actions. AI Markdown is rendered through DOM elements and text nodes; HTML is never interpreted. The model is an educational explainer, not a source of current facts or personalized calculations. If the request fails or the key is absent, the UI falls back to local guidance.

The function reads `GROQ_API_KEY` from its environment and uses `GROQ_MODEL` when configured, otherwise `openai/gpt-oss-20b`. The key, prompt, model response, and SDK error details are not written to application logs. API responses are not cached (`Cache-Control: no-store`).

The endpoint validates POST/JSON requests, limits questions to 1,000 characters and bodies to 4 KB, caps model output at 400 tokens/2,000 returned characters, and applies an in-memory per-IP limit of 12 requests per 15 minutes. Serverless instances do not share this memory, so it is not a reliable production-wide rate limit. Apply an edge/firewall limit before making the endpoint public. Do not provide a payment execution tool.
